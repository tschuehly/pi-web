# Session-topic trial issue ledger

Branch-only experiment `experiment/session-topic-ui-20260924`; not installed or approved for rollout. This ledger tracks the image-delivery slice and the remaining owner decision. The earlier topic-routing findings were addressed in the trial before this slice; this document is not a full installed-app issue inventory.

| Issue | Diagnosis | Current status and evidence |
| --- | --- | --- |
| TOPIC-IMG-01 · Pending paste could lose images | Paste bypassed the disabled attach control; completion cleared all drafts. | Fixed in trial: paste/add reject pending posts; the queued-post component test checks that a pasted image does not replace the original. |
| TOPIC-IMG-02 · Misleading image retry | Reattachment was disabled, changing bytes conflicts with the original request ID, and an unknown delivery was labeled “not recorded.” | Fixed in trial: missing image bytes and 409 conflicts disable retry; notice says delivery is unconfirmed and directs the owner to check history. The conflict/discard component test and HTTP status test pass. |
| TOPIC-IMG-03 · Tab closure could duplicate a queued image | Image bytes persisted in IndexedDB but their request ID lived only in tab-scoped sessionStorage. | Fixed for tab closure in trial: bytes and request ID share one IndexedDB record before delivery; the new-tab test clears sessionStorage and verifies reuse of the original ID. A simultaneous cross-tab write race has not been separately verified and remains pending. |
| TOPIC-IMG-04 · Image-heavy polling | Each two-second streaming poll fetched full image histories. | Fixed in trial: unchanged topic summary version skips the detail fetch; a component regression checks both unchanged and changed summaries. |
| TOPIC-IMG-05 · Failed storage read masked drafts | A failed IndexedDB read became an empty image list, permitting overwrite. | Fixed in trial: image operations are disabled and the read failure is shown; a component regression checks no save after the failure. |
| TOPIC-IMG-06 · Invalid image conversion retry loop | The same invalid bytes always failed conversion but the UI invited retry. | Fixed in trial: conversion errors are marked non-retryable and the local draft can be discarded. This exact failure path has not had a new live regression test. |
| TOPIC-UX-01 · Topic progress is hard to scan | The trial rail previews the latest message; the split prototype used manually authored summaries and the marketing pipeline used explicit stages. | **Pending Thomas’s direction.** No new status board, timeline, or stages were implemented. Recommend comparing a concise per-topic activity/status strip with the message-list and stage variants before choosing. |

Verification (2026-09-24): 142 focused image/topic/API tests and 84 adjacent client tests passed; all changed TypeScript passed scoped ESLint; `npm run typecheck` exited 0; `npx vite build` succeeded. The staged verification rerun passed cached typecheck, Knip, ESLint, and 2,264 related tests across 190 files (one skipped); the first commit-hook attempt exited 1, with its exact failure not retained. A browser post from the isolated QA session saved the image and request ID together, then persisted the image in the topic while clearing the local record on acceptance. The complete `npm test` suite was not rerun after this change; earlier broad attempts had unrelated build/Docker/terminal/concurrency failures. The original independent review identified the image findings; a fresh independent remediation review did **not** launch because the model catalog timed out, so the fixes do not have an independent final verdict.
